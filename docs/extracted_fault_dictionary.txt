Document Overview
This dictionary organizes elevator diagnostic knowledge into five subsystems. Each subsystem lists
components, sensors/observable data, failure modes, and signal-to-root-cause mappings. These are candidate
hypotheses for the RCA engine — not confirmed diagnoses. Live reasoning must evaluate correlated evidence
before promoting any candidate to a diagnosis.
Subsystem
Scope
1. Drive / Motor
Power conversion, drive, motor, motion generation
2. Door System
Door operator, sensors, lock/interlock, cycle mechanics
3. Brake / Traction
Brake, sheave, ropes/belts, governor, safety gear
4. Controller / Safety-Circuit
PLC, I/O, safety chain, relays, event logging
5. Sensors / Instrumentation
Measurement layer providing RCA evidence
RCA Principle
Overcurrent is a symptom, not a root cause. The same fault code can have multiple upstream causes. The
RCA engine needs correlated evidence across subsystems, not a simple lookup.

Cross-Subsystem Correlation Examples
These examples show why alarm correlation before RCA matters: multiple alarms can be consequences of one
underlying fault.
Example 1 — Drive vs Brake
Motor Current ↑ + Brake Timing Violation + Speed Deviation
RCA considers three hypotheses:
  Drive / Motor fault
 Brake fault
 Mechanical load problem
The system must use available evidence to distinguish hypotheses — not simply conclude "overcurrent = motor
fault."
Example 2 — Door + Controller
Door Closed Signal Unstable + Door Reopening + Safety Chain Open
Possible single causal chain:
 Door-lock contact degradation
→ Interlock opens
→ Safety chain opens
→ Controller generates hard fault
What looks like multiple faults may actually be one causal chain.
Example 3 — Sensor → Controller → Motion
 Encoder Signal Abnormal
→ Position Deviation
→ Leveling Error
→ Controller Fault / Stop Event
→ RCA traces back toward Encoder / Position Sensing
Recommended Knowledge-Base Hierarchy
For implementation, structure the knowledge base as:
Subsystem → Component → Failure Mode → Observable Signal → Evidence Pattern → Plausible Root
Cause → Verification Test → Corrective Action
Example — Drive / Motor
 DRIVE / MOTOR
→ IGBT Power Module
→ IGBT Short Circuit
→ Overcurrent + drive fault
→ High current + abnormal DC-bus behavior
→ IGBT failure (candidate)
→ Verify drive fault with motor-side isolation/test procedure
→ Technician repair/replacement
Example — Door System
 DOOR SYSTEM
→ Roller / Bearing
→ Mechanical Wear
→ Door-cycle time ↑ + motor current ↑

Taxonomy vs Diagnosis
The "plausible root causes" in this dictionary are candidate hypotheses. The live RCA pipeline should only
promote one to a diagnosis after evaluating the available evidence. Project documentation explicitly requires
evidence-linked reasoning rather than an LLM simply guessing the cause.
